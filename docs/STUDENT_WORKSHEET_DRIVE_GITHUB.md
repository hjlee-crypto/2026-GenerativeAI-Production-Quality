# 생성형 AI 기반 생산·품질 데이터 분석 및 시각화 — 실습 워크시트

성결대학교 산업경영공학과 4학년 | 80분 | Google Colab·Gemini·Julius AI(선택)

## 실습 목표와 현장 상황

- 제조기업의 생산라인 A·B·C에서 생산계획 달성률과 불량률이 서로 다르게 나타납니다. 생산관리 담당자는 계획 차질을, 품질관리 담당자는 주요 불량을 파악해야 합니다.

- 목표: ① 생산계획 달성률·불량률·시간당 생산량 계산 ② 생산라인 비교와 불량 유형 파레토 분석 ③ AI의 분석을 검증하고 개선 가설 제안.

- 최종 산출물: 차트 2종 이상 + 분석 결과 3문장 + 개선 제안 1건. 모든 데이터는 교육용 합성 데이터입니다.

## A. Colab을 처음 사용하는 학생 — 내 Drive에서 실행하기

- ① 교수자 GitHub 저장소 페이지에서 녹색 Code → Download ZIP을 클릭합니다. 다운로드된 ZIP을 PC에서 압축 해제합니다. (교수자 GitHub의 파일을 직접 실행하지 않습니다.)

- ② 내 Google Drive → 새로 만들기 → 폴더를 선택하고 production_quality_ai_workshop 폴더를 만듭니다.

- ③ 압축 해제한 data 폴더와 notebooks 폴더를 내 Drive의 production_quality_ai_workshop 폴더에 업로드합니다. 최종 경로는 내 드라이브/production_quality_ai_workshop/data/production_daily.csv 등입니다.

- ④ Drive에서 notebooks/production_quality_workshop_DRIVE.ipynb를 찾아 우클릭 → 연결 앱 → Google Colaboratory로 엽니다. 표시되지 않으면 연결 앱 → 앱 더보기에서 Colaboratory를 연결하거나 Colab의 파일 → 노트 업로드로 내 PC의 ipynb를 업로드합니다.

- ⑤ Colab에서 파일 → Drive에 사본 저장을 선택합니다. 사본 이름을 본인 식별 가능한 이름으로 변경합니다. 사본은 Drive의 Colab Notebooks 등에 저장될 수 있습니다.

- ⑥ 첫 코드 셀을 실행(▶ 또는 Shift+Enter)합니다. Google Drive 연결 승인 창이 나오면 본인 계정의 권한을 확인하고 승인합니다. 데이터 표가 나타나는지 확인합니다.

- ⑦ FileNotFoundError가 나오면 Drive의 폴더명과 파일명, 첫 코드 셀의 DATA_DIR 경로를 대조합니다. Drive 폴더를 다른 위치에 저장했다면 DATA_DIR를 실제 경로로 수정합니다.

- ⑧ 다음 코드 셀들을 위에서 아래로 실행합니다. 코드 셀은 실행 가능, Markdown 셀은 설명용입니다. 런타임이 초기화되면 첫 셀부터 다시 실행합니다.

## C. 교수자 GitHub 자료를 내 GitHub로 가져오기

- 방법 1 — Fork: 교수자 GitHub 저장소에서 Fork → Create a new fork → 본인 계정과 저장소 이름 확인 → Create fork. 원본과 연결된 개인 저장소가 생성됩니다. 저장소가 공개인지 확인합니다.

- 방법 2 — 독립 복사: 교수자 저장소 Code → Download ZIP → 압축 해제 → 내 GitHub에서 New repository 생성 → Add file → Upload files → 압축 해제한 파일·폴더 업로드 → Commit changes. ZIP 파일만 올리지 말고 내부 파일 구조를 유지합니다.

- 내 GitHub에 가져왔다고 해서 내 Drive에 자동 저장되는 것은 아닙니다. Colab 실습은 위 A 또는 B 절차에 따라 내 Drive의 파일을 사용합니다.

## 실습 1 — 생산관리: 계획 대비 실적 분석 (약 15분)

## 실습 2 — 품질관리: 불량률과 파레토 분석 (약 20분)

- 왜 하는가? 불량 유형별 발생 비중을 확인하여 개선 활동의 우선순위를 정하기 위해서입니다.

- 불량률 = 불량 수량 합계 ÷ 실제 생산량 합계 × 100. 파레토 차트는 유형별 불량 건수 내림차순 막대와 누적 비율 선으로 구성합니다.
